# Jones Agent v1.0 发布说明（macOS）

> 面向用户。开发/打包细节见 [docs/release.md](../release.md)；产品定义见
> [docs/PRD.md](../PRD.md)。

## 这是什么

Jones 是一个装在你自己电脑上、自主运行的通用 AI 工作体。以对话为核心，配备
文件、终端、浏览器、互联网调研、媒体生成、办公文档等全域能力，在你授权的边界
内自主完成多步骤工作，全程可观察、可拦截、可回放。

核心原则：本地优先（数据只存 `~/.jones/`，零遥测）、无账号 BYOK（不注册登录
订阅，只需你自己的模型 Key）、动作可拦（改变外部世界的动作默认经你批准）、
失败诚实（错误显式呈现，永不假装成功）、不可逆删除永不执行（任何模式、任何
授权都无法覆盖）。

## 支持什么

- **三栏工作台**：左右栏可独立开关；主会话（唯一、常驻）+ 子会话，会话归属
  Project。
- **Project 工作区**：以目录路径为锚点；同目录下的 Session 归组管理。
- **Agent 配置**：人设、语气、原则、工具白名单、Skill 集合、模型偏好可自定义，
  一个 Agent 可绑多个 Session。
- **BYOK 多厂商模型**：设置页配置 Key，Session / Agent 级别可指定模型，Key
  永不完整回显。声明支持六家厂商（Anthropic、OpenAI、DeepSeek、Qwen、Gemini、
  Ollama）——**实测覆盖情况见下方「已知问题」**。
- **权限三道闸**：规则闸 → 审查闸 → 用户闸，拒绝即不执行；不可逆删除永不执行，
  任何授权不可覆盖。
- **Run 回放**：每个 Run 的 Step 序列可完整回放（参数、结果、耗时、审批结果）。
- **文件五件套**：读 / 写 / 编辑 / 搜索 / 目录遍历，受 Project 工作区与权限闸
  约束。
- **终端**：执行命令、流式输出、可中断；高危命令走权限闸。
- **浏览器**：Jones 专属常驻 Chrome profile，登录态跨重启保留；导航 / 读页 /
  点击 / 填表。
- **互联网与深度调研**：搜索 + 抓取 + 多步调研，产出带引用的报告。
- **Cron 定时任务**：Cron 表达式 + prompt 模板触发 Task → Run，结果推回主
  会话；连续失败 3 次自动停用并提醒。
- **Skill 加载**：文件形式加载，内置办公文档生成（Markdown → Docx/PDF/表格）
  与媒体生成（图/音/视频）两项。
- **MCP 接入**：stdio 与 HTTP 两种 MCP Server 均可接入，工具进入能力注册表与
  透明页。
- **失败诚实与错误面板**：网络 / 配额 / 工具异常显式呈现，重试 / 换模型 /
  放弃的选择权交给用户。
- **常驻守护进程**：注册为系统用户级服务（launchd），Electron 关闭后运行时
  仍存活；进程重启后排队中的外发动作不自动重放。
- **能力透明页**：展示本轮给 Agent 装配了哪些工具、隐藏了哪些、为什么。

## 怎么装

v1.0 目前**没有经过 Apple 公证的签名安装包**（见下方「已知问题」）。当前唯一
验证过的安装路径是从源码构建：

1. 环境：macOS 13+（Apple Silicon 已验证；Intel 见下方已知问题）、
   [uv](https://docs.astral.sh/uv/)、Node 22 + pnpm 10。
2. 克隆本仓库，执行 `scripts/release/build-mac.sh arm64`，产出
   `build/release/dist/Jones-<version>-arm64.dmg`（构建脚本会依次打 daemon
   bundle、`apps/desktop` 产物、electron-builder 打包、ad-hoc 签名）。
3. 打开 dmg 把 `Jones.app` 拖进「应用程序」。**首次打开会被 Gatekeeper 拦截**
   （ad-hoc 签名不是 Apple 信任的 Developer ID，这是预期行为，不是 bug）——
   在「访达」里右键 `Jones.app` → 「打开」，在弹出的确认框里再次点「打开」；
   或者终端执行 `xattr -cr /Applications/Jones.app` 后正常双击。
4. 首次启动 Jones.app 时，如果检测不到 daemon 在跑，Electron 会自动把打包
   产物里的 daemon 可执行文件直接拉起来，不需要手动操作。但这个兜底路径**不
   经过 launchd**——如果想要「随系统登录自启、崩溃后自动拉起」的常驻行为
   （PRD FR15），需要自己手动执行一次以下命令把它注册成 launchd LaunchAgent
   （**`--program` 必须带上**，指向这条 wrapper 脚本本身的绝对路径）：

   ```
   /Applications/Jones.app/Contents/Resources/daemon/bin/jones-daemon \
     service install --program \
     "/Applications/Jones.app/Contents/Resources/daemon/bin/jones-daemon"
   ```

   不带 `--program` 时装出来的 `ProgramArguments` 会用 `sys.executable`
   （打包产物里是 `python/bin/python3.12`），绕开这层 wrapper 设置的
   `PYTHONPATH`——daemon 进程能拉起，但加载不到 Hermes，跑 Turn 时才会报错。
   带 `--program` 是目前唯一验证过跑得通的形式，见 `docs/release.md` §5。
   首次安装时自动完成这一步还未接入安装流程，属于已知缺口。

## 已知问题

### daemon 退出阶段偶发卡住（#35，P0，追踪中）

**现象**：同一 Session 走过一次真实 ACP 权限往返（弹过一次权限确认框）之后，
第二次调用 daemon 的 `send()`，进程退出阶段偶发卡在事件循环空转，不会自己
退出。

**用户可感知的影响**：关掉 Jones App 后，daemon 进程可能不会自己退出，会
一直挂在后台，不是「晚一会儿」就自行消失。它不会响应新请求，也不会做任何
有害的事——只是需要手动清理才能真正结束（见下方「临时处理办法」）。

**临时处理办法**：如果需要确认 daemon 已完全退出（例如要重装或排查问题），
用 `ps aux | grep jones_daemon` 确认进程仍在时手动 `kill` 掉即可；下次启动会
重新拉起一个干净的进程，不影响已保存的数据。

**追踪**：[Issue #35](https://github.com/nativeas/jones-agent/issues/35)。

### Intel（x86_64）架构：CI 已能产出，尚未在 Intel 真机上跑过

`cryptography`（daemon 的依赖之一）从 50.0.0 起不再发布 macOS x86_64 wheel，
而 Hermes 内核把它 exact-pin 在 50.0.0，降版本这条路是堵死的。因此 x86_64
产物无法在 Apple Silicon 主机上交叉构建，只能在原生 Intel 机器上从源码编译。

**已解决**：`.github/workflows/release-bundle.yml` 用两个原生架构的 runner
各自出包——`macos-15-intel` 出 x86_64、`macos-14` 出 arm64。x86_64 那条确实
在 runner 上用原生 Rust 从 sdist 编译出了 `cryptography==50.0.0`（约 2 分 47 秒）。
[实际 CI 运行记录](https://github.com/nativeas/jones-agent/actions/runs/35693372847)，
两个 job 均成功。

**仍待做**：CI 目前只产出 daemon bundle 这一层，完整的 `.dmg`（electron-builder
打包 + 签名）还没接进 CI；x86_64 产物也还没有在一台真正的 Intel Mac 上安装
运行过（G18 的手工验收部分）。所以 Intel 支持是「构建链路已打通、真机未验证」，
不是「已验证可用」。

详见 [Issue #36](https://github.com/nativeas/jones-agent/issues/36) 与
[docs/release.md](../release.md) §2.2。

### 六厂商 BYOK：目前只有 DeepSeek 走过真实端到端验证

BYOK 的 Key 存取、校验、路由、六厂商协议适配层都有自动化测试覆盖；但「配一个
真 Key、真的对该厂商发起一次带工具调用的 Turn 并成功」这件事，目前只在
DeepSeek 一条路径上跑过真实网络请求验证过（`JONES_E2E=1` 门控的真实 Hermes
端到端测试，认任一厂商 Key；本机跑通的是 DeepSeek Key，见
[Issue #38](https://github.com/nativeas/jones-agent/issues/38)）。Anthropic、
OpenAI、Qwen、Gemini、Ollama 五家的协议适配代码存在且有单元测试，但尚未拿
真实 Key 跑过完整 Turn。逐厂商实测记录见
[docs/acceptance/v1.0/G02.md](../acceptance/v1.0/G02.md)（目前六行
「待执行」）。

### 真实模型 E2E 测试互相干扰（#40，P1，仅影响开发者）

两条使用真实模型的端到端测试连续跑时会互相干扰（孤儿进程检查在「文件五件套」
用例之后必失败），怀疑是测试隔离问题而非产品侧回收缺陷，尚未查清根因。这两条
测试都被 `JONES_E2E=1` 门控，CI 与普通 `make check` 都不会跑到，**不影响
终端用户，也不影响 v1.0 的正式发布状态**。追踪：
[Issue #40](https://github.com/nativeas/jones-agent/issues/40)。

### 正式签名与公证尚未执行（#33）

本机没有 Apple Developer Program 账号，v1.0 目前只有 ad-hoc 签名，没有经过
Apple 公证。这意味着 Gatekeeper 会拦截首次打开（见上方「怎么装」的绕过步骤）。
追踪：[Issue #33](https://github.com/nativeas/jones-agent/issues/33)。

- **G18** Intel 真机验证（见上方 #36）
