## 自动化边界（round-1 review fix，评审 #1/#4）

`daemon/tests/acceptance/test_g19_data_migratable.py` 复用
`daemon/tests/integration/test_migrator_upgrade_e2e.py::
test_current_build_opens_a_database_created_by_the_previous_build`：用上一个
真实 git 版本（`v0.9-pre` tag）起一个真实 daemon 建出真实 `JONES_HOME`，再用
当前版本的 daemon 打开同一个 `JONES_HOME`，断言会话/Agent 完整存活——这是"整
目录拷到另一处（这里是另一个版本）后数据完整可用"的字面证明，覆盖 G19/N17 的
**版本升级**那一半。

这条覆盖有两层门控，CI/`make check-daemon` 下都会命中：

1. 目标测试模块级 `skipif(not JONES_E2E)`——`JONES_E2E` 在 CI 与本地默认
   `pytest -q` 下都未设置。
2. 即使设了 `JONES_E2E=1`，目标测试的 fixture 还要求本机存在 `v0.9-pre` 这个
   **从未推送到 remote** 的本地 tag（`git ls-remote --tags origin` 为空，也没
   有任何 CI 步骤会创建/拉取它）；不存在时 fixture 自身 `pytest.skip`。

**此前的问题**：acceptance 测试直接把 `run_existing` 透传给目标测试，而
`run_existing` 当时只断言子进程 `returncode == 0`——pytest 对"全部 skip"同样
返回 0，所以上面两层门控无论命中哪一层，CI 里这一格都显示"通过"，实际上从未
执行过任何断言。已在本轮修复：

- `_reuse.py` 的 `run_existing` 现在额外要求子进程输出里出现 `passed` 且不
  出现 `skipped`，命中即失败（见该文件 docstring）。
- `test_g19_data_migratable.py` 自己加了 `skipif(not JONES_E2E)`：默认情况下
  这条 acceptance 测试如实显示为 `skipped`（未验证），而不是借内层的 skip
  伪装成 `passed`。`JONES_E2E=1` 且本机有 `v0.9-pre` tag 时，会真的跑一遍并
  要求真实通过；`JONES_E2E=1` 但 tag 缺失时，现在会如实失败（而不是继续悄悄
  通过）。

**这条覆盖没有证明、也无法证明的**：G19 字面要求的"`~/.jones/` 整目录拷到
**另一台机器**"——目标测试只用了同一台机器上的另一个 git 版本，没有跨越不同
操作系统/文件系统/架构。这是本文档「步骤」部分要补的那一半。

## 前置条件

- 两台机器（或至少两个独立的用户目录/文件系统边界），装有同一份 Jones 构建。
- 一个已经产生过真实数据的 `~/.jones/`：至少一个 Project、一个 Agent、几条
  Session 历史消息、一个已配置的 Key。

## 步骤

1. 在机器 A 上正常使用 Jones 一段时间，积累真实的 Project/Agent/Session
   历史（含至少一次工具调用留下的记忆占位）。
2. 完全退出 Jones（daemon 一并停止），把整个 `~/.jones/` 目录拷贝（不是软链）
   到机器 B（或同机另一用户目录）。
3. 在机器 B 上设置 `JONES_HOME` 指向拷贝后的目录，安装同一版本的 Jones，
   启动。
4. 重录 Key（B 上没有 A 的 Key，需要重新走一遍 Provider 设置）。
5. 检查：Project/Agent 列表完整、Session 历史消息完整可读、能否继续在原
   Session 上发消息并正常工作。

## 期望

- 会话历史、Agent 定义、Skill 完整可见，没有截断或损坏的记录。
- 重录 Key 后能继续在原 Session 上正常工作（模型能看到历史上下文）。
- 不需要手工修数据库/改 schema 才能打开。
